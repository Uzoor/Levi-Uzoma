02 — How I build

The boring parts are the job

Anything works on the happy path. These are the habits that decide whether it still works when a third-party API has a bad morning.

01Idempotent triggers
The same event arriving twice does not create the record twice. Replays are safe.
02Retry with intent
Third-party APIs fail. Workflows back off and retry rather than silently dropping the run.
03Duplicate suppression
Dedupe keys per record and per recipient, so nobody is notified twice about the same thing.
04Logs an operator can read
Every run writes a timestamped entry, so you can see what fired and what failed without opening the canvas.
05Documented for handover
Schemas and flow notes help somebody else take the system over without me in the room.
06Self-hosted and maintained
I run my own n8n on AWS EC2 with Docker, so I own the upgrades and the breakages too.
